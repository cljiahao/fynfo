## Changes delivered

- Restricted auth callback destinations to same-origin local paths; fixed exact
  public API routing and prevented forged action headers from bypassing API auth.
- Authenticate before resolving vault keys. Lock immediately hides/unmounts
  financial UI and clears queries even when the network stalls. Household locked
  state also hides cached goals and actions.
- Logout now shares one implementation, clears both key cookies before auth
  logout, and supports retry from the locked screen. Cookie teardown remains
  available after auth expiry without reading cookies or accessing a database.
- Removed plaintext ticker allocation storage and discards its old browser entry.
- Failed profile/snapshot/salary/planner/relief reads no longer expose writable
  fallback values. Single-record backend reads throw opaque errors on failure
  and return null only on successful absence. Relief UI waits for save success.
- Cancelled pending blur/autosave timers on unmount, blocked late export downloads,
  and narrowed optimistic expense rollback to its original query and affected
  row versions. Concurrent successes and cleared caches survive failed writes.
- Checked child replacement errors, stopped deletion racing failed parent writes,
  and encrypts replacement children before destructive operations. These paths
  are still not database transactions.
- Fixed insurance-only planner NaN, mixed settled/unsettled owed totals, and sell
  fees in money-weighted cash flows. Preserved existing financial model contracts
  where changing them would require an agreed definition.
- Use normalized parsed trade values. Quote fetching validates inputs/upstream
  data, caps requests to 100 tickers and five workers, and sets ten-second fetch
  deadlines. Invalid data preserves existing best-effort unavailable results.
- Enforce canonical 32-byte base64 vault keys. Database/unknown-error logging
  retains classifications and context without raw private values or error stacks;
  request IDs are generated server-side.
- Invite PBKDF2 runs asynchronously with byte-identical key parameters. A local
  fixture observed scheduled-work delay of 163ms synchronously versus 39ms
  asynchronously; this establishes responsiveness, not higher throughput.
- Reuse currency formatters. One Node fixture benchmark of 20,000 SGD formats
  measured 986.56ms before versus 18.23ms after; no page/production latency claim.
- Removed seven unconsumed files: six generated UI primitives and the obsolete
  vault migration helper. Removed the unused react-dropzone dependency.
- Updated existing Next.js and eslint-config-next from 16.2.6 to 16.3.8 for
  published security maintenance. No new direct dependency was added.
- Personal export version 2 includes dividends; it still excludes household
  data. Public/security copy now describes client PIN derivation and server
  encryption/decryption accurately. README reflects the current stack and tools.
- Added trailing-comment lint enforcement with tooling-directive exceptions;
  removed narration and preserved necessary format/unit/fixture explanations as
  standalone comments. Updated formatter exclusions and secret ignore patterns.
- Query test doubles now isolate tables and record exact ownership filters.
  Tests exercise denied boundaries instead of silently passing fixture skips.
  test:ci now enforces existing coverage floors and empty test discovery fails.

## Unresolved decisions and permission-dependent work

1. **P1 database authorization:** authenticated callers can reset their own vault
   throttle with success=true; invite consumption lacks secret proof inside its
   transaction; household membership/capacity races violate the one-household,
   two-member contract. See FD01–04 for exact SQL evidence. Fix with reviewed
   forward migrations, a trusted reset boundary, common-row serialization,
   membership constraints and real concurrent/direct-RPC negative tests. Existing
   conflicting memberships need a data plan; no blind deletion.
2. **P1 session binding:** sealed key cookies contain keys without server-checked
   user binding or expiry. Logout cleanup improves the ordinary path but does not
   make replayed envelopes safe. A separately approved envelope transition must
   bind purpose/user/expiry, reject stale keys, and account for existing sessions.
3. **P2 atomicity/history:** child replacement and relief replacement can still
   lose data on insertion failure/concurrent writes; histories/export can truncate
   at Supabase's row limit. Use transactional replacement and stable pagination,
   with real SQL and 1,001-row/nested-relation tests. Saved snapshot edits now
   preserve parent IDs; new-month upsert conflicts across sessions still need a
   transactional database solution.
4. **P2 financial definitions:** cost basis after sales, mixed-currency totals/IRR,
   missing-price/FX presentation, impossible dates, current versus historical tax
   bands/relief years, CPF age/residency/monthly ceilings need agreed contracts and
   official-rule fixtures. FD09–13/F13 document evidence. Existing tests sometimes
   encode the current wrong model, so test counts alone are insufficient.
5. **Telemetry/admin:** direct Data API policies/RPC grants permit ingestion and
   aggregate reads outside application checks. Review FD16's database boundary;
   browser event validation alone cannot provide abuse prevention or SQL auth.
6. **Governance/enforcement:** some financial deletes use auth-only guards despite
   the mandatory vault rule (FD17). Decide and enforce the intended exceptions;
   existing historical approvals need reconciliation. Actual harness read guards,
   permission-based protected edits, LF/hash alignment and manifest regeneration
   require explicit scoped approval. Do not merely update hashes to hide drift.
7. **Frontend debt:** keyboard sorting, additional field labels, per-currency
   presentation, inline styles and feature-barrel/page orchestration drift remain
   in the frontend ledger. These need scoped follow-up rather than an aesthetic
   redesign or an arbitrary long-file threshold.
8. **Lint:** the owner approved SonarJS4.2.0, now installed alongside ESLint with
   no-commented-code, no-identical-functions and no-collection-size-mischeck.
   Existing comment conventions remain enforced; the broad preset is not enabled.

The previously declined server-pepper proposal remains an accepted owner risk in
spec 007; this audit did not silently change PIN/key derivation or recoverability.

## Owner continuation: coverage, reported bugs and runtime

The saved-snapshot edit failure was reproduced against the existing parent/child
foreign-key contract. All edits now update the existing authenticated row and
reuse its ID, including unchanged-month edits. The regression checks the saved
encrypted amount and child ID. The form also rejects duplicate-month submission
at the submit boundary; concurrent creation still needs a database solution.

Additional reproduced bugs fixed: empty trade dates throwing before validation;
failed trade/dividend deletion escaping without feedback; clipboard denial during
invite copying; earlier failed expense submissions losing notifications after a
later submission. Telemetry now accepts only supported public paths, preventing
private query/fragment text from being persisted through the HTTP boundary.

offline PIN guessing against encrypted rows, existing member household-deletion
policy and non-atomic child replacements remain documented limitations.
