## Findings

- P1 F1: `src/features/assets/components/investment-allocation.tsx:43` saves a ticker-keyed allocation map as plaintext localStorage (`fynfo-allocations`), via `src/lib/utils/local-store.ts:21`. Actual held ticker identifiers survive vault lock/signout and cross-account use. Stop persisting that map in browser storage; use ephemeral state until an approved encrypted persistence path exists, and remove legacy stored entries. Regression: change allocation, lock/signout, verify sensitive storage absent.
- P1 F2: `src/features/auth/hooks/use-idle-lock.ts:56-64` clears cache and flips locked only in fetch.finally. A pending network request can delay auto-lock indefinitely. Immediately lock locally and clear cached financial data before awaiting bounded best-effort cookie deletion. Regression: unresolved fetch still promptly locks/clears.
- P1 F3: `src/features/auth/components/vault-unlock-flow.tsx:183` is a plain fixed div while `src/app/dashboard/layout.tsx:30-31` keeps underlying children mounted. No focus trap/inert/modal semantics; Tab can leave overlay and screen readers can traverse financial UI and locally retained edited data. Use the existing modal primitive with non-dismissable lock semantics and unmount financial content on lock; coordinate hydration/unlock refetch. Regression: tab cycle, screen reader structure, open edit dialog before idle lock.
- P2 F4: `src/features/profile/components/profile-form.tsx:155-177` ignores query errors and renders editable DEFAULT_PROFILE after a failed initial read. Saving can overwrite a real profile with fallback values. Render explicit retryable error state; only default on successful absence. Regression: rejected getProfile exposes no saveable fallback.
- P2 F5: `src/features/expenses/components/sortable-header.tsx:24-26` makes a th clickable without keyboard focus/activation or aria-sort. Use a button inside th and aria-sort on active header. Regression: keyboard sorting and announced direction.
- P2 F6: `src/features/auth/components/vault-unlock-flow.tsx:225-249` PIN field has no label/name (masked placeholder is insufficient). Add associated label and error description. Salary form gross/bonus labels similarly lack htmlFor/input IDs; split-dialog name/amount/settled controls and relief amount/count/variant controls need contextual accessible names.
- P3 F7: hard-rule architecture drift: `src/app/dashboard/(overview)/page.tsx:24-43` fetches through deep action imports, admin/page.tsx:14 fetches directly, and many cross-feature components/hooks bypass barrels. Move page data orchestration into feature boundary; publish only required exports and replace cross-feature deep imports. Audit historic specs before treating all exceptions as unapproved.
- P3 F8: `src/app/dashboard/admin/page.tsx:12` comment names ADMIN_USER_IDS while active contract uses ADMIN_EMAILS. Correct stale constraint narration.
- P3 F9: inline styles occur in vault progress, chart legends, category swatches, deployment bars, and planner results, contrary to constitution §3.2. Replace fixed palette styles with token classes; dynamic width approach needs governance-compatible strategy. No recommendation to introduce a dependency.

## Second sweep findings (current code evidence)

- P2 F10 (Batch D fixed): snapshot, salary and planner read failures exposed replacement defaults or cached-error edits. Final guards in `snapshot-form.tsx`, `salary-form.tsx`, and `salary-planner.tsx` remove editable controls until reads succeed; snapshot list failure also blocks duplicate-blind new records. Retry preserves query contracts. Planner pending autosave now clears on unmount. `use-prices.ts:14` now sorts a copy, preserving caller arrays.
- P2 F11 (Batch K fixed): `src/features/expenses/components/editable-expense-row.tsx:134-136` schedules a draft save without unmount cleanup. Deleting/leaving/locking during 400ms blur can invoke a stale write. Add effect cleanup of the timer and test unmount before timeout; no redesign needed.
- P2 F12 (Batch G fixed): `src/features/salary/components/tax-reliefs-dialog.tsx:192-202` ignores failed reads and seeds default reliefs. Confirm calls replacement mutation then closes/updates displayed reliefs immediately (`:86-91`) without success/error handling. Guard failed reads (including cached errors) with Retry; close/update parent only on successful persistence and surface opaque failure. Supplemental Batch G records and fixes this read/save boundary.
- P2 F13: `src/features/equity/components/portfolio-summary.tsx:52-60` adds native USD/SGD costs and values, labels the sum SGD, and builds one mixed-unit IRR. Unrealised P&L still displays when quotes fail (`:148-159`). Narrow fix: display per-market native totals or explicitly converted presentation with unavailable FX/quotes; historical cash-flow exchange semantics must be agreed before calling combined IRR valid. `trade-table.tsx` labels US trade values through SGD formatter; `yield-on-cost-table.tsx` uses SGD TTM income over native holding cost. Do not invent a cross-currency protocol during cleanup.
- P1 F14 (Batch G fixed): `src/features/household/components/household-overview.tsx:67,107-112` renders cached goals/create/invite UI even when authoritative session says locked. `useGoals(false)` stops fetching but retains cached data. Gate those consumers with `!locked` and test populated cache with locked household; personal VaultGate alone does not establish the independent household-lock contract.
- P2 F15 (Batch G fixed): `src/features/marketing/components/hero.tsx:72`, `security-band.tsx:7-13,35-39`, and `src/features/profile/components/export-data-card.tsx:22-24` promise device-only encryption/decryption and keys/plaintext never reaching servers. Actual actions decrypt/encrypt server-side; `use-export-data.ts:40-73` explicitly fetches server-decrypted data. Correct public/export copy to the implemented trust boundary; no crypto change. Backup excludes dividends and household, so "complete" is also unsupported.
- P2 F16 (Batch K fixed): `src/features/expenses/hooks/use-expenses.ts:46-65,99-111,134-146` snapshots/restores the entire query cache for each mutation. Concurrent quick-add failure restores an earlier snapshot, losing later successful rows in UI; error after query clear can recreate plaintext cached data. Roll back only the affected entity/version and avoid writing to a removed cache; test overlapping success/failure and clear-before-rejection. Empty initial cache rollback also leaves failed optimistic row because `previous` is undefined.
- P2 F17 (Batch K fixed): `src/features/profile/hooks/use-export-data.ts:40-80` can finish and download plaintext after its component is unmounted by lock. Track mounted/request generation and suppress download if lock/unmount happened; test deferred domain reads resolving after unmount. Successful server-side reads cannot be retroactively cancelled, but browser disclosure can be stopped.

The second sweep also confirmed delete dialogs in snapshot/salary/trade/dividend tables await failed mutations without opaque failure feedback; paged tables do not clamp the page after record deletion; missing profile/FX/quote reads are commonly shown as real default values. These are residual UX/data-quality issues rather than evidence of missing server authorization. No raw HTML sink, dynamic script execution, or secret-file access was found in this owned domain.
